# M26.1 — Architectural Baseline (Frozen)

**Status:** Frozen. This document is the stable reference point for everything built under M26.1 (`packages/engineering-review`) — implemented invariants and public extension points, as they stand pending operational verification (see `M26.1-INDEX.md` for the full document set this baseline draws from). Future slices and any M26.2/M26.3 work should treat this as the contract they build on top of, not something to casually reopen.

## What "frozen" means here

Architecturally complete, manually reviewed line by line against the domain model and ADRs, but **not yet operationally verified** — no successful `pnpm install`/`lint`/`typecheck`/`test`/`test --coverage` run has occurred (no working package registry access in the environment this was built in). "Frozen" describes the design and code as written, not a claim that it's been proven to run. Any issues that surface once verification runs should be treated as bugs against this baseline, not as license to redesign it.

## Implemented invariants (enforced in code, `packages/engineering-review/src/EngineeringReviewReport.ts`)

1. A review cannot leave `Draft` without at least one `EvidenceReference` (`collectEvidence`).
2. A `Finding` cannot be constructed without at least one `EvidenceReference` (`createReviewFinding`), and cannot be added to a review citing evidence that review never recorded (`addFinding` — throws `MissingEvidenceReference`).
3. A `Recommendation` cannot be constructed without at least one supporting `Finding` (`createReviewRecommendation`), and cannot be added citing a finding the review never recorded (`addRecommendation` — throws `MissingFindingReference`).
4. A `Published` review is immutable — every mutating method (`addEvidence`, `addFinding`, `addRecommendation`, `decideVerdict`, `publish`) throws `InvalidLifecycleTransition` once state is `Published`.
5. `EvidenceReference`s are append-only — re-adding an existing id throws `DuplicateDomainIdentifier`; there is no update/remove method at all.
6. `Finding`s never overwrite previously recorded `EvidenceReference`s — enforced by the append-only evidence list plus the cross-reference check in (2).
7. `Recommendation`s cannot introduce claims untraceable to their referenced `Finding`s — enforced structurally: a `Recommendation` has no constructor path that doesn't require `findingRefs`.
8. `PolicyEvaluation` (value object, unused as of this baseline) is recorded as a delegated outcome, not computed by the domain — the type exists so Slice 5 can populate it without a model change.
9. Every `Finding`/`Recommendation` is traceable to `Provenance` via `EvidenceReference` — structural, not a runtime check, since there's no construction path that omits it.
10. None of the above ever touches `CanPublishWorkflow` or `WorkflowValidator` — this package has zero dependency on either; nothing in it could produce that side effect even accidentally.
11. A `Verdict` cannot exist before `RecommendationsGenerated` (`decideVerdict` — throws `InvalidLifecycleTransition` if attempted earlier).
12. A `Published` review cannot exist without a `Verdict` (`publish` — throws `DomainInvariantViolation` if attempted without one).

Additional identifier-integrity guarantees added since the initial Slice 1 pass: duplicate `Finding`/`Recommendation` ids are rejected the same way duplicate `EvidenceReference` ids are (`DuplicateDomainIdentifier`), and a `Verdict` referencing an unrecorded `Recommendation` is rejected (`MissingRecommendationReference`).

## Public extension points

- **`IEngineeringReviewRepository`** (`ports/IEngineeringReviewRepository.ts`) — `save`/`load`/`findLatest`/`findByWorkflow`/`findByManifest`/`findByVerdict`. One implementation shipped: `InMemoryEngineeringReviewRepository`. A real adapter (Slice 3) implements this same interface — no change to the interface itself implied.
- **`ISnapshotProvider`** (`ports/ISnapshotProvider.ts`) — `getSnapshot(workflowId)`. One implementation shipped: `FixedSnapshotProvider`.
- **`IReviewContributor`** (`ports/IReviewContributor.ts`) — `execute(context) -> ContributorResult`. One implementation shipped: `ArchitectureReviewContributor`. This is the contract every future contributor (Security, Cost, Compliance, Release, per the Phase 6 roadmap sketch) implements.
- **`RecommendationStrategy`** (`application/RecommendationStrategy.ts`) — `synthesize(findings) -> Recommendation[]`. One implementation shipped: `OneRecommendationPerFindingStrategy`. Explicitly not assumed 1:1 by the orchestrator itself.
- **`VerdictStrategy`** (`application/VerdictStrategy.ts`) — `decide(findings, recommendations) -> Verdict`. One implementation shipped: `SeverityBasedVerdictStrategy`.
- **`EngineeringReviewOrchestrator`** (`application/EngineeringReviewOrchestrator.ts`) — the composition root all of the above plug into; takes an `ISnapshotProvider`, an `IEngineeringReviewRepository`, a contributor list, and the two strategies (both defaulted).

## Explicitly not part of this baseline

- Timeout/cancellation contributor statuses — deferred by design; a `TIMEOUT` status without real deadline/cancellation infrastructure behind it would be cosmetic (agreed explicitly in review).
- Policy-driven verdicts/recommendations — Slice 5, not built.
- Real persistence, event publication, contributor registry/DAG ordering — Slices 3 and 6, not built.
- Any API projection layer, caching strategy, or Studio UX — **not proposed as an accepted specification by this baseline.** Discussed only as name-only future direction; would need its own PRD/ADR pass before implementation, per the correction already made earlier in this project's history.
