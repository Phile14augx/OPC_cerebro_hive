# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope boundary (locked, see CONTEXT.md / REQUIREMENTS.md "Out of Scope"):** This is a wiring/integration phase, not a visual redesign. Studio's visual system (`apps/studio/app/theme/*.css`) is treated as frozen. This contract's job is to lock how four narrow, new/changed surfaces **compose from existing tokens and components** — it does not introduce new colors, fonts, spacing units, or primitives:

1. `PlaceholderModule` — new shared component (D-06/D-07)
2. `Sidebar.tsx` group-rendering fix (D-13) — behavioral fix, not a restyle
3. CerebroForge's 9 live pages — loading/error/empty state consistency for now-real data (FORGE-01)
4. FORGE-02 fake-data removal — replace fabricated stats/buttons with `PlaceholderModule`

A lightweight breadcrumb component (D-08) is also in scope (titles/breadcrumbs only, per CONTEXT.md).

## Spacing Scale

Declared values (must be multiples of 4) — these are the values already in active use across `forge/*` pages and `Sidebar.tsx`; this phase does not add new ones:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), badge internal padding |
| sm | 8px | Compact row padding (`p-2`, `gap-2`), nav item icon gaps |
| md | 16px | Default card/section padding (`p-4`), nav section `px-3` |
| lg | 24px | `space-y-6`, card padding on `PlaceholderModule` inner spacing |
| xl | 32px | `p-8` on `PlaceholderModule`'s outer `Card`, `space-y-8` between major page blocks |
| 2xl | 48px | Not used within this phase's 4 surfaces (reserved for page-level marketing sections elsewhere) |
| 3xl | 64px | Not used within this phase's 4 surfaces |

Exceptions: `PlaceholderModule`'s wrapping container uses `min-h-[60vh]` (viewport-relative centering, not a spacing-scale value) to vertically center the card in the content area — this is layout sizing, not spacing, and matches RESEARCH.md's Pattern 2 example verbatim.

## Typography

Reusing the project's existing fluid type scale (`app/theme/typography.css`) — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 light / 500 dark (`--font-weight-body`, theme-driven) | 1.5 (dark) / 1.6 (light), via `--line-height-body` |
| Label (eyebrow/group tag) | 12px (`text-xs`), `uppercase tracking-widest font-bold` | 700 | 1.4 |
| Heading (`PlaceholderModule` H1, section headers) | 18px (`text-lg`) | 700 light / 800 dark (`--font-weight-heading`) | 1.2 |
| Display (page H1, e.g. "Backend Studio") | 30px (`text-3xl`) | 700 light / 800 dark | 1.2 |

Do not introduce a 5th size or a 3rd weight for any of the four in-scope surfaces. `PlaceholderModule`'s status line ("Status: Planned") uses the existing `Badge` component's own type treatment (`text-xs font-bold`) — do not hand-style it separately.

## Color

Reusing existing CSS-variable tokens (`app/theme/colors.css`) — no new hex values introduced. Values below are token names, which resolve differently per light/dark theme (the app already supports both; components must reference tokens, never hardcoded hex).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `bg-surface` (`--bg-page`, `--bg-surface`) | Page background, main content canvas, `PlaceholderModule`'s outer flex container |
| Secondary (30%) | `bg-surface-elevated`, `border-border` (`--bg-surface-elevated`, `--border-default`) | `Card` backgrounds (placeholder card, error banners, forge tool cards), `Sidebar` background (`bg-background` + `border-border` divider), nav section dividers |
| Accent (10%) | `text-primary-accent` / `--text-accent` (emerald-500 light / neon-500 dark) | Reserved for exactly: (1) active sidebar nav item text+icon+background tint (`bg-primary-accent/10 text-primary-accent`), (2) primary `Button` variant background, (3) `:focus-visible` outline/ring, (4) links (`variant="link"`). **Not** used on `PlaceholderModule` itself (informational, deliberately neutral) and **not** used for the new Sidebar groups' default (inactive) state — those stay `text-text-secondary`/`text-text-muted` per the existing pattern. Per-tool brand hues already established inside individual Forge pages (violet for AI Planner, emerald for Deployment Studio, purple for Backend Studio's pre-existing badges, amber for the CerebroForge sidebar group) are a separate, pre-existing per-tool accent convention — do not repurpose the primary accent token to replace them, and do not invent new per-tool hues for FORGE-02's replacement placeholders (those use the neutral `PlaceholderModule`, no tool-hue accent). |
| Destructive | `text-danger` / `--text-danger` (red-500 light / red-400 dark), paired with `border-red-500/20 bg-red-500/5` on the containing `Card` | Error banners only (forge-api call failures). No destructive *actions* (delete/disable) exist in this phase's scope — FORGE-02 removes fake buttons, it does not add new destructive ones. |

Accent reserved for: active sidebar nav item, primary CTA buttons (`Button` default variant), focus rings, text links. Never the placeholder icon, never inactive nav items, never decorative use.

## Component Contracts

### 1. `PlaceholderModule` (new — `app/(platform)/app/components/ui/PlaceholderModule.tsx`)

Composition (locked): `Card` (outer, centered via a `min-h-[60vh] flex items-center justify-center` wrapper) → icon chip (`w-12 h-12 rounded-xl bg-surface-elevated border border-border`, centers a single `lucide-react` icon at `size={22}` in `text-text-muted` — **never** in the accent color, this is a neutral/informational state) → eyebrow (`{group} / {title}`, `text-xs font-bold uppercase tracking-widest text-text-muted`) → heading (`Not yet available`, `text-lg font-space font-bold text-text-primary`) → body copy (`text-sm text-text-secondary`) → `Badge variant="secondary"` showing `Status: {Planned|Disabled}`.

Props (locked shape): `{ group: string; title: string; status: "planned" | "disabled" }`. No `onClick`/CTA prop — this component is informational only, never interactive beyond whatever global nav already exists.

Applies to: all `planned`/`disabled` registry entries rendered via the catch-all route, all 10 FORGE-02 unbacked CerebroForge pages (replacing their existing fake content in place — same component, same props shape, group=`"CerebroForge"`), and the fallback for unregistered/orphaned paths.

### 2. Breadcrumb (new, lightweight — Studio-local, D-08)

Prop shape: `{ label: string; href?: string }[]`, rendered as `label` (`text-text-secondary`) separated by a `ChevronRight size={12} className="text-text-muted"`, last item unstyled-as-link in `text-text-primary font-bold` (current page, no href). Do **not** port `components/discovery/Breadcrumbs.tsx` (marketing-site component — emits `JsonLd`, uses shadcn `text-foreground` tokens per RESEARCH.md's Anti-Pattern note). Source of truth for both breadcrumb and page `<title>` is the same navigation registry entry matched by the current path — one lookup, two consumers, per D-08.

### 3. `Sidebar.tsx` group-rendering fix (D-13 — behavioral, not visual)

The 6 currently-unrendered groups (HiveOps, Automation, Research, Academy, Business, Support) must render through **the exact same visual treatment already coded** for the existing `sections.map(...)` block (lines ~219-261 of the current file): `text-xs font-bold uppercase tracking-widest text-text-muted` section header, `space-y-0.5` item list, each item using the existing active/inactive class ternary (`bg-surface-elevated text-text-primary font-bold shadow-sm border border-border` when active, `text-text-secondary hover:bg-surface hover:text-text-primary border border-transparent` when inactive). No new visual variant is introduced for these 6 groups — they must be visually indistinguishable in styling from the 6 groups already rendering today, differing only in which titles/items appear. Do not give newly-surfaced groups a "new" badge, highlight color, or different spacing to call attention to them.

### 4. FORGE-01 loading/error/empty consistency (no visual redesign — consistency pass)

Every one of the 9 live pages must expose all three states using the patterns already established elsewhere in the same file tree (see `requirements/page.tsx`, `deploy/page.tsx`, `testing/page.tsx`, `review/page.tsx`, `docs/page.tsx` for existing precedent — `planner/page.tsx` and `codegen/page.tsx` are the known gaps per RESEARCH.md and must be brought in line, not given a new pattern):
- **Loading:** centered `Loader2` (`size 20-40` depending on context) + present-participle status text in `text-text-secondary`, OR inline `"Loading…"` in a name/value slot — match whichever precedent already exists on that specific page; do not switch a page from one to the other.
- **Error:** `Card className="p-4 border-red-500/20 bg-red-500/5"` containing `AlertTriangle size={16} className="text-red-400 shrink-0"` + `<p className="text-sm text-red-400">{error}</p>` + (new, per Copywriting Contract) a `Try again` ghost button.
- **Empty:** `"No project selected"` when `!projectId`, shown in the page's existing context-banner/status-line slot (not a full-page takeover — Forge pages remain otherwise usable/browsable without a project).

### 5. FORGE-02 fake-data removal (D-15)

For each of the 10 unbacked pages (`forge/backend`, `forge/database`, `forge/api`, `forge/mobile`, `forge/web`, `forge/desktop`, `forge/bots`, `forge/repos`, `forge/ui-studio`, `forge/monitoring`... — note `forge/monitoring` currently renders real-looking mock `StatCard`/alert data per RESEARCH.md, treat identically to `forge/backend`): delete the fabricated `StatCard` rows, fake generated-item lists, and any button wired to `setTimeout` (e.g. `backend/page.tsx`'s "Generate Backend" button). Replace the entire page body with a single `<PlaceholderModule group="CerebroForge" title="{Nav item title}" status="planned" />`. Do not keep any of the removed page's decorative chrome (icons, per-tool color badges, runtime selectors) — those imply functionality that doesn't exist, which is exactly what D-15 prohibits.
