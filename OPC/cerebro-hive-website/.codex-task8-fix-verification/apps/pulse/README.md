# HivePulse — Executive AI Command Centre

> **CerebroHive AEOS · Month 1 · Claude-primary product · Production-ready**

HivePulse is the real-time executive intelligence layer of the AEOS platform. It gives the C-suite a single pane of glass across all 50 AEOS products, with zero human assembly of reports or dashboards.

## Routes

| Route | Description |
|-------|-------------|
| `/dashboard/mission-control` | Live enterprise health score (0–100), pillar breakdown, KPI drill-down |
| `/dashboard/briefings` | Autonomous briefings (daily/weekly/board) — generated by Claude from live DB data |
| `/dashboard/scenarios` | Scenario modelling: Claude analyses what-if hypotheses with pillar-level impact |
| `/dashboard/alerts` | Strategic alert feed from Prisma (Alert + Incident tables) — Claude enriches actions |
| `/dashboard/war-room` | Crisis coordination: Claude acts as Incident Commander, coordinates all AEOS agents |

## Architecture

```
apps/pulse/
  app/
    api/
      health/route.ts           ← GET  composite health score (Prisma + platform-api), Redis 30s cache
      alerts/route.ts           ← GET  strategic alerts; POST acknowledge
      briefings/route.ts        ← GET  list; POST generate via Claude
      briefings/[id]/route.ts   ← GET  single briefing
      scenarios/route.ts        ← GET  list; POST create + Claude analysis
      stream/health/route.ts    ← SSE  live health score every 30s
    dashboard/
      mission-control/page.tsx  ← useQuery /api/health + /api/alerts
      briefings/page.tsx        ← useQuery /api/briefings; useMutation POST /api/briefings
      scenarios/page.tsx        ← useQuery /api/scenarios; useMutation POST /api/scenarios
      alerts/page.tsx           ← useQuery /api/alerts; useMutation POST /api/alerts (acknowledge)
      war-room/page.tsx         ← useQuery /api/alerts (critical count)
  shared/
    lib/
      types.ts                  ← All TypeScript types
      db.ts                     ← Prisma singleton from @cerebro/db
      redis.ts                  ← ioredis singleton + cacheGet/cacheSet helpers
      platform-client.ts        ← HTTP client for platform-api (telemetry/overview, health/services)
      claude-client.ts          ← Anthropic SDK — generateBriefing, enrichAlertActions, analyseScenario
      health-score.ts           ← Composite health score engine (5 pillars × real Prisma queries)
      alert-mapper.ts           ← Maps Prisma Alert/Incident rows → StrategicAlert
    ui/
      AppShell.tsx              ← Sidebar + header, live clock, QueryClientProvider
      PulseCard.tsx             ← PulseCard, StatusDot, TrendBadge, SeverityBadge
      globals.css               ← Design tokens (CSS variables)
```

## Real data sources

| Layer | Source | What it provides |
|-------|--------|-----------------|
| **Prisma** (`@cerebro/db`) | `AgentExecution`, `Alert`, `Incident`, `Metric`, `HealthCheck` tables | Agent success rates, alerts, incidents, KPI metrics, briefing/scenario storage |
| **Platform-API** (`NEXT_PUBLIC_PLATFORM_API_URL`) | `/telemetry/overview`, `/health/services` | RPM, latency, error rate, service health |
| **Anthropic Claude** (`ANTHROPIC_API_KEY`) | `claude-sonnet-4-6` | Briefing generation, alert action enrichment, scenario analysis |
| **Redis** (`REDIS_URL`) | `ioredis` | 30s health cache, 60s alert cache, 2h briefing list cache, 1h briefing body cache |

## Health score algorithm

5 pillars weighted to 0–100 composite score:

| Pillar | Weight | Inputs |
|--------|--------|--------|
| Revenue | 25% | Metric table (mrr, arr, conversion) |
| Operations | 25% | AgentExecution success rate + platform-api telemetry |
| People | 20% | Metric table (retention, engagement, headcount) |
| Risk | 15% | Open Incident count + critical Alert count |
| Market | 15% | Metric table (nps, churn, csat) |
