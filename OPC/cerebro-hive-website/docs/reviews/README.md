# Reviews

Point-in-time review, audit, and handoff documents — evidence of a review that happened, not living documentation. If a review surfaces a finding that changes how the system should be described going forward, update the relevant permanent document (`../architecture/`, `../domains/`, etc.) and leave the review here as the record of when and why.

| Location | Contents |
|---|---|
| [`audit/`](./audit/) | The M26.x architecture/engineering audit batch — context diagrams, bounded contexts, domain model, service boundaries, persistence model, extension framework, plus SEO/accessibility/analytics audit data (CSVs) |
| (this folder, flat) | Dated audit reports, master-plan gap assessment, Codex changeset/review/handoff notes, triage reports, database migration investigation, twin-studio master-spec gap audit, [2026-08-13-day1-production-foundation.md](./2026-08-13-day1-production-foundation.md) |

## What doesn't belong here

- Ongoing work → `../plans/active/`
- Current architecture → `../architecture/`
- Fully superseded/abandoned material → `../archive/`
