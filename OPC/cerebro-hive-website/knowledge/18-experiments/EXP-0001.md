# EXP-0001: Always-On Agent Prototype — Temporal.io Daemon Mode + NATS Subscription

```yaml
id: "EXP-0001"
title: "Always-On Agent Prototype — Persistent Daemon Agent via Temporal.io + NATS"
source_knowledge:
  - "KN-AGENT-000001"   # Claude Conway — always-on agent pattern
  - "KN-AGENT-000002"   # Event-Driven Agent Trigger Architecture
  - "KN-AGENT-000004"   # Agent Memory Architectures — required for stateful persistence

hypothesis: >
  Temporal.io "continue-as-new" workflow pattern, combined with NATS JetStream event
  subscription, can implement a Conway-equivalent always-on persistent agent in the
  Cerebro Nexarch stack within 3 weeks of engineering effort. The agent will:
  (1) persist across event firings without losing task context,
  (2) wake within 5 seconds of a subscribed NATS event arriving,
  (3) maintain conversation memory across firings using services/memory-service,
  (4) pass all existing HiveShield authorization checks on tool invocations.

success_criteria:
  - "Agent instance survives service restart (Temporal.io durable state)"
  - "NATS event to agent execution: ≤5 seconds (p95)"
  - "Agent recalls prior session context from memory-service on wake"
  - "Agent correctly declines tool calls not on its allow-list (IMP-0003)"
  - "100 sequential event firings with no context loss or memory corruption"
  - "Single agent instance running cost: <$0.10/hour at idle (no polling)"

failure_criteria:
  - "Temporal.io continue-as-new creates unacceptable workflow history bloat"
  - "NATS event routing to specific agent instance requires >2 weeks to implement"
  - "Memory retrieval latency >500ms per firing makes agent unresponsive"
  - "HiveShield authorization adds >1s overhead per tool invocation"

scope: >
  Single-agent prototype only. One agent type: "Monitor Agent" that:
  - Subscribes to NATS topic: system.alerts.>
  - On event: logs the alert, retrieves recent alert history from memory, determines severity
  - If HIGH severity: invokes a notification tool (mock)
  - Stores event to memory with TTL 30 days
  - Returns to dormant state awaiting next event
  
  NOT in scope for EXP-0001:
  - Multi-agent event subscription coordination
  - External webhook ingress (IMP-0001 full implementation)
  - Production security hardening (uses test-only HMAC bypass)
  - Horizontal scaling across multiple swarm-runtime replicas

components_involved:
  - "services/swarm-runtime"      # Temporal.io continue-as-new workflow
  - "services/memory-service"     # episodic memory between firings
  - "packages/agent-sdk"          # agent.subscribe() prototype API
  - "NATS JetStream"              # event delivery substrate
  - "packages/hiveshield-policy"  # authorization enforcement (IMP-0003 prerequisite)

dependencies:
  - "IMP-0003 (Per-Agent Tool Authorization) must be at least partially implemented"
  - "services/memory-service persistent storage (Tier 2 episodic memory) partially implemented"
  - "NATS JetStream operational (already deployed)"
  - "Temporal.io operational (already deployed)"

time_box: "3 weeks"

engineering_effort: MEDIUM
# Estimated: 1 engineer × 3 weeks. Primitives (Temporal.io, NATS) exist.
# Novel work: continue-as-new agent loop design, NATS→Temporal routing bridge,
# memory retrieval integration in agent firing context.

risk_level: LOW
# Experiment is scoped to a test environment; does not touch production agent paths.
# Temporal.io and NATS are already in production — no new infrastructure risk.

expected_outputs:
  - "Working prototype: always-on Monitor Agent running in development environment"
  - "Benchmark report: wake latency, memory retrieval latency, idle cost"
  - "Architecture decision record: Temporal.io continue-as-new vs alternatives"
  - "Recommendation: proceed to IMP-0001 full implementation OR pivot to alternative"
```
