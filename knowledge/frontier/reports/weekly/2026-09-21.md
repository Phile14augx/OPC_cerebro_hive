## Executive signal

The strongest signal is a convergence, not a new framework: agent execution requires an enforcement
envelope outside the model. The APort Vault release reports zero unpermitted simulated transfers
behind deterministic pre-action authorization across 89,406 evaluated protected cases, while
Red-Teaming Auto Mode reports a 79% arbitrary-command success rate against monitor-only controls.
NIST IR 8587 adds final workload-token guidance, and Pydantic AI patched SSRF, denial-of-service,
domain-normalization, and telemetry-redaction defects in agent web-fetch paths. Together these
strengthen the existing `TECH-AGENT-HARNESS-TRUST-001` recommendation: policy must execute before
tools and sensitive context, with short-lived identity, complete traces, and adversarial verification.

Two evaluation developments are also strategic. NIST ARIA now specifies a combined model-test,
red-team, and user-test planning method. MLPerf Inference v6.1 adds end-to-end RAG and edge-agentic
workloads, providing a credible basis for evolving KRN-019 beyond model-only scores.

No implementation was authorized or started. Wave 0 remains the only engineering stream; current
repository work is W0.2, and knowledge-derived implementation remains blocked by W0.3/W0.4/W0.5,
canonical-runtime consolidation, and WIP governance.

### 1. Policy-bound agent execution envelope

- **Evidence:** [APort Vault Benchmark v1](https://huggingface.co/datasets/aporthq/vault-benchmark-v1),
  [Red-Teaming Auto Mode](https://arxiv.org/abs/2609.19587),
  [NIST IR 8587](https://csrc.nist.gov/News/2026/protecting-tokens-and-assertions-nist-ir-8587),
  and [Pydantic AI v2.44.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.44.0).
- **What changed:** independent channels now cover tool authorization, monitor bypass, workload
  identity, SSRF/DoS, and telemetry leakage within one week.
- **Limits:** APort is a simulated banking domain and its corpus is gated; Red-Teaming Auto Mode is
  dual-use and its code has no detected license; NIST guidance is not an agent-IAM standard.
- **Nexarch mapping:** extend the canonical policy/tool/approval/audit planes. Do not add another
  agent framework or policy engine.
- **Security:** pre-action policy, destination/amount constraints, short-lived workload identity,
  default-deny network fetch, bounded parsing, and trace redaction are required.
- **Convergence:** 9/10 — benchmark + paper + standard + maintained framework advisory.

### 2. Holistic AI evaluation planning

- **Evidence:** [NIST ARIA Evaluation Planning Manual](https://www.nist.gov/publications/aria-evaluation-planning-manual-elements-aria-style-ai-evaluations).
- **What changed:** NIST published a reusable planning method combining model testing, red teaming,
  and user testing.
- **Nexarch mapping:** adopt as the planning skeleton for KRN-019 and AO-06, retaining Nexarch
  acceptance criteria and evidence levels.
- **Limit:** ARIA is guidance, not a turnkey evaluation implementation or certification.

### 3. Agentic and RAG performance benchmarking

- **Evidence:** [MLPerf Inference v6.1](https://mlcommons.org/2026/09/mlperf-inference-v6-1-results/).
- **What changed:** MLCommons introduced end-to-end RAG ingestion/query and edge-agentic coding
  workloads; 30 organizations submitted 120 systems.
- **Reported movement:** best per-accelerator VLM performance improved 2.99× over v6.0 and
  DeepSeek-R1 5.7× year-over-year.
- **Nexarch mapping:** reuse workload structure and accuracy gates; do not copy results into a model
  registry without reproducing them on Nexarch workloads and hardware.

### 4. Vulnerability localization evaluation

- **Evidence:** [paper](https://arxiv.org/abs/2609.15939) and
  [Apache-2.0 artifact](https://github.com/cisco-foundation-ai/vulnerability-localization-benchmark).
- **What changed:** 500 disclosed vulnerabilities across 290 repositories, six ecosystems, and 147
  CWE categories were released with 27-model and four-analyzer results.
- **Reported baseline:** best File-F1 is 0.229; 38.4% of tasks receive no correct localization.
- **Nexarch mapping:** a candidate benchmark for KRN-019, HiveForge, AO-06, SG-01, and SG-02.
- **Limit:** patch-touched files are an incomplete oracle and repository snapshots retain upstream
  licenses.

### 5. Auditable harness optimization

- **Evidence:** [SoL-Pi paper](https://arxiv.org/abs/2609.20519) and
  [MIT repository](https://github.com/NVlabs/SoL-Pi).
- **What changed:** four learned harness mechanisms address execution, context compaction,
  observations, and delegated reading.
- **Reported result:** 44.7–49.0% lower token traffic and roughly one-third lower API cost on 51
  EdgeBench tasks at comparable performance.
- **Nexarch mapping:** test techniques inside the canonical runtime; compaction must preserve policy,
  provenance, audit, and failure evidence.
- **Limit:** author-reported, small benchmark, expensive search, and backend-dependent activation.

- **Convergence:** policy-bound agent execution is now supported by benchmark, attack research,

  changing execution authorization.

  pressure. Nexarch should specialize in portable policy, evidence, and evaluation rather than
  duplicate provider runtimes.

  enterprise differentiation is shifting from generic model access to governed data, semantics, and
  workflow evidence.

  vendor benchmark claims.
