# M26.2/M26.3 — Vertical Slice Baseline (Frozen)

**Status:** Frozen, 2026-07-29. This is the stable reference point for the persistence/eventing/transport layer (M26.2, ADR-006) and the contributor extension model (M26.3, ADR-007) built on top of `M26.1-BASELINE.md`. It closes out `audit/ARCHITECTURAL-REVIEW-UNPLANNED-VERTICAL-SLICE.md` and its two reconciliation documents. Future work builds on this as a contract, the same way M26.1 was treated once frozen.

## What "frozen" means here

Unlike M26.1's freeze, this one **is** operationally verified — real command output, run by you, against the actual repository and the actual deployed AWS environment, at every step. Nothing here rests on inference alone.

## Accepted architecture

- **ADR-006** — DynamoDB (`DynamoDBEngineeringReviewRepository`) as the Operational Store, S3 (`S3EvidenceStore`) as the Immutable Evidence Store, SNS→SQS (`SNSReviewEventPublisher`) for integration events, REST via API Gateway + a single Lambda handler, `@cerebro/api-client`'s hand-rolled client (with its generated OpenAPI document adopted as a contract-verification artifact, not yet wired into CI — tracked, not blocking), Cognito for auth, React Query in Studio.
- **ADR-007** — `ports/IReviewContributor.ts` as the sole contributor interface; `contributors/sdk/` and `InProcessContributorHost` retired; `ContributorRegistry` as the real composition root, constructing all five contributors (`ArchitectureReviewContributor` plus Security/Compliance/Cost/Reliability) and wired into `EngineeringReviewOrchestrator` via `getEnabled()`.

## What's real vs. what's honestly not yet

- **Real:** `ArchitectureReviewContributor` — the only contributor with actual analysis logic (a nodeCount/edgeCount complexity threshold).
- **Honestly not yet:** `SecurityReviewAgent`, `ComplianceReviewAgent`, `CostReviewAgent`, `ReliabilityReviewAgent` — registered, correctly typed, but each reports `status: 'skipped'` with zero evidence/findings, because no real analyzer logic exists for any of them. This was nearly compromised mid-build: a since-reverted revision had these three report `'succeeded'` with fabricated, hardcoded findings that could not be derived from anything `ReviewContext` actually contains. Caught, reverted, and recorded in ADR-007's addendum. Building real analysis logic for any of these four is legitimate future work — this baseline does not pretend it's done.
- **Real composition root:** `ContributorRegistry` — confirmed to exist and wire all five contributors together; this resolved a gap the review had flagged (no composition root existed anywhere outside test files).
- **Not yet built:** dependency-DAG ordering among contributors (deferred to a future slice, same as M26.1 deferred it — unchanged by this baseline), a Studio workflow-picker UI (reviews are reachable at `/reviews/[workflowId]` but nothing in Studio links there yet), and a CI check enforcing the hand-rolled API client against its generated OpenAPI document.

## Explicitly not part of this baseline

- Real analyzer logic for Security/Compliance/Cost/Reliability contributors.
- Contributor dependency-DAG ordering.
- A Studio workflow-picker UI.
- CI-enforced contract verification between `@cerebro/api-client` and its generated OpenAPI document.
- Any migration of Studio's API endpoint configuration off build-time env vars to Secrets Manager/Parameter Store — explicitly deferred in ADR-006 until this deployment moves off its current dev/shared-integration lifecycle.
- A full workspace build/test baseline — a separate, later exercise, not a condition of this freeze.
