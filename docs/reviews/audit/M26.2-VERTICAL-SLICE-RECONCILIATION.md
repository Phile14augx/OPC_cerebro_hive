# M26.2/M26.3 Reconciliation: Classifying the Unplanned Vertical Slice

**Status:** Classification pass only. This document decides *what each component is relative to the existing ADRs/architecture docs* — it is not itself the M26.2/M26.3 PRD/ADR (that follows, per task #74/#75), and it authorizes no code changes yet.

**Basis:** `audit/ARCHITECTURAL-REVIEW-UNPLANNED-VERTICAL-SLICE.md` (inventory, §3) cross-referenced against `ADR-001`–`ADR-005`, `M26.1-ARCHITECTURE-05-PERSISTENCE-MODEL.md`, `M26.1-ARCHITECTURE-06-EXTENSION-FRAMEWORK.md`, and `M26.2-M26.3-DISCOVERY-NOTES.md`. | `SecurityReviewAgent`, `ComplianceReviewAgent`, `CostReviewAgent`, `ReliabilityReviewAgent` | **Adopted (honest no-ops)** | Rewritten against `ports/IReviewContributor.ts`, registered through the new `ContributorRegistry` composition root. ## Net shape after this pass

Two components are clean adopts (`DynamoDBEngineeringReviewRepository` fully, `S3EvidenceStore`/`SNSReviewEventPublisher`/handler/api-client/Studio UI with named fixes). Three components should not survive as-is (`contributors/sdk/` interface, `InProcessContributorHost`, and by extension the four stub agents' current code, though not their category names). One component (the live AWS endpoint) isn't a classification question at all — it's a factual one that has to be answered before it can be adopted, replaced, or removed, and it's the one item here with a real operational-security dimension (an undocumented live credentialed endpoint), not just an architectural-tidiness one.
