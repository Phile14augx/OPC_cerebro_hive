## 1. Product Overview

**HiveEvaluation™** is the systematic quality assurance platform for all AI outputs in the Intelligence Mesh. It acts as the mandatory quality gate before any model, agent, or workflow reaches production, and as the continuous monitoring layer after deployment.

The fundamental problem: you cannot know if your AI is working correctly without rigorous measurement. HiveEvaluation makes that measurement automatic, reproducible, and regulator-defensible.

---

## 2. Evaluation Dimensions

HiveEvaluation scores AI outputs across seven dimensions:

| Dimension | Definition | Measurement Method |
|---|---|---|
| **Groundedness** | Does the output accurately reflect the source documents? | Fact-checking against retrieved context |
| **Faithfulness** | Does the output avoid introducing information not in the context? | Entailment classification |
| **Completeness** | Does the output address all parts of the input query? | Coverage scoring |
| **Coherence** | Is the output logically structured and internally consistent? | LLM-as-judge + human rubric |
| **Toxicity** | Does the output contain harmful, offensive, or policy-violating content? | Classifier (Perspective API + custom) |
| **Bias** | Does the output treat different groups consistently and fairly? | Counterfactual fairness testing |
| **Task Accuracy** | Does the output correctly complete the intended task? | Task-specific automated checks |

## 3. Core Capabilities

### 3.1 Eval Studio (Rubric Builder)
- Visual interface for creating evaluation rubrics for specific use cases.
- Rubric templates for common AI use cases (RAG Q&A, summarization, classification, code generation, agent task completion).
- Custom rubrics: define dimension weights, acceptance thresholds, and measurement methods.
- Rubric versioning — evaluation criteria are version-controlled alongside the models they evaluate.

### 3.2 Benchmark Dataset Management
- Create and manage curated benchmark datasets (question/answer pairs, task/expected-output pairs).
- Human annotation workflow: send samples to subject matter experts for ground truth labeling.
- Dataset versioning and provenance (who created it, when, from what source).
- Automatic dataset expansion: identify evaluation blind spots and suggest additional test cases.

### 3.3 Eval Runner
Three trigger modes:

**Pre-deployment (CI/CD Gate)**
- Triggered automatically by HiveForge when a new model/prompt/agent is published.
- Runs full benchmark suite against the new artifact.
- Pass/fail decision: blocks deployment if any dimension score falls below configured threshold.
- Comparison mode: scores new version against current production baseline. Regression in any dimension blocks deployment.

**Post-deployment (Continuous)**
- Samples production traffic (configurable %, default 1%).
- Runs sampled requests/responses through the evaluation suite.
- Tracks quality metrics over time; alerts on degradation trends.

**On-demand**
- Manual eval run triggered by any user with eval:run permission.
- Useful for investigating specific failure modes or evaluating model candidates.

### 3.4 LLM-as-Judge
For dimensions that resist rule-based measurement (coherence, helpfulness, tone), HiveEvaluation uses a separate "judge" LLM:
- Judge model is a different model from the model under evaluation (prevents self-evaluation bias).
- Structured scoring rubric provided to the judge as a system prompt (not free-form opinion).
- Multi-judge ensemble: 3 judge runs per sample, score averaged (reduces variance).
- Judge model is itself periodically evaluated against human annotation ground truth to detect judge drift.

### 3.5 Automated Red Team (Safety Evaluation)
- Adversarial test suite generated by HiveShield's attack library.
- Tests every deployed model/agent for known vulnerability categories (prompt injection susceptibility, PII leakage under specific inputs, jailbreak resistance).
- Results integrated into the overall quality score (safety failures automatically fail the gate).

### 3.6 Eval Reports
- Per-deployment evaluation report (PDF + JSON): scores on all dimensions, sample inputs/outputs with scores, comparison to baseline, pass/fail verdict with reasoning.
- Trend dashboards: quality score over time per model/agent, regression heatmaps, dimension drift charts.
- Regulatory-grade reports: audit-ready format with methodology documentation, benchmark dataset citation, and evaluator credentials.

## 4. Technology Stack

| Component | Technology |
|---|---|
| Eval Framework | DSPy (metric definitions) + custom Python evaluation harness |
| Groundedness / Faithfulness | RAGAS framework (extended) |
| Toxicity Detection | Perspective API + custom fine-tuned classifier |
| Bias Detection | Fairlearn + counterfactual test generator |
| LLM-as-Judge | Configurable (default: Claude 3.5 Sonnet — different from evaluated model) |
| Benchmark Store | PostgreSQL (dataset metadata) + HiveStorage (sample blobs) |
| Pipeline | Apache Airflow (eval job scheduling) |
| Report Generation | Python + WeasyPrint (PDF) |

---

## 5. Integration Points

| Integration | Details |
|---|---|
| HiveForge | Eval suite runs as pre-deployment gate; failing evals block artifact publication |
| HiveOps | Post-deployment continuous eval feeds quality metrics into HiveOps rollback decisions |
| HiveObservatory | Eval metrics streamed to Observatory dashboards |
| HiveShield | Safety evaluation uses HiveShield's adversarial test library |
| HiveGovern | Every eval run and result logged for audit trail |

## 6. SLAs

| Metric | Target |
|---|---|
| Pre-deployment eval completion time | <30 minutes for standard benchmark suite |
| Continuous eval sampling latency | <5 seconds added to production request (async path) |
| Eval result availability | <1 minute after eval run completes |
| Judge LLM accuracy vs. human annotation | >85% correlation (measured monthly) |
