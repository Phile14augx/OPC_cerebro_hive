<objective>
Close the FORGE-01 gap: make all 9 backend-backed CerebroForge pages honestly expose their three data states — loading, error (with a working retry), and empty — so a user always knows whether they are looking at a real forge-api result, a failure, or nothing selected.

Purpose: CONTEXT.md D-02 chose functional implementation for these 9 pages because `services/forge-api` already works. RESEARCH.md confirms the wiring is ~90% done; what is missing is the honest-state surface. D-04 caps this at "usable, not decorative" — no deep UX polish, no streaming work, no new API surface.
Output: 9 pages that render `error` when set, offer a `Try again` that re-invokes the specific failed action, and show `No project selected` when `projectId` is absent.
</objective>

<phase_goal>
**As a** CerebroHive Studio user, **I want to** click any destination in the sidebar and land on either a working page or a clearly-labelled "not yet available" page, **so that** I never hit a 404, a dead link, or fabricated data while navigating the product.

This plan owns the "working page" half of that story for CerebroForge's 9 backed tools.
</phase_goal>

| Boundary | Description |

| browser → forge-api (port 4005, `NEXT_PUBLIC_FORGE_API_URL`) | Client-side `fetch` from Studio directly to NestJS; no Next.js server intermediary |
| user input → forge-api DTOs | Prompt strings and project IDs cross into `PlanBodyDto` and siblings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information Disclosure | New error banners rendering `error` verbatim | mitigate | `request()` in `lib/forge/api-client.ts` composes the message as `forge-api {status}: {body}`. Render it through React text interpolation only — never `dangerouslySetInnerHTML`. Do not add `console.error(err)` of the raw response object, and do not surface `NEXT_PUBLIC_FORGE_API_URL` or request headers in the banner |
| T-01-05 | Spoofing / Elevation of Privilege | `services/forge-api` — none of the 9 controllers use `@UseGuards`; `@ApiBearerAuth()` is Swagger annotation only; `forgeApi.request()` sends no `Authorization` header | accept (deliberately deferred) | **Known pre-existing gap, explicitly out of Phase 1 scope** per CONTEXT.md D-04 and 01-VALIDATION.md's Security Domain note. Fixing it is Phase 2 territory (WKSP-05's shared tenant-scoping helper). This plan makes the gap *more visible* (errors now render) but does not widen it: no new endpoint, no new client, no credential handling |
| T-01-06 | Information Disclosure | forge-api `projects.list()` accepts an optional `workspaceId`/`organizationId` filter that nothing enforces — a caller can enumerate other orgs' projects | accept (deliberately deferred) | Same rationale as T-01-05. | T-01-07 | Input Validation | Prompt/ID payloads to forge-api | transfer | Already mitigated server-side: `services/forge-api/src/main.ts` installs a global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })` and DTOs use `class-validator`. No new DTO is introduced by this plan |
| T-01-SC | Tampering | npm/pnpm installs | mitigate | No packages installed. `lucide-react` (`AlertTriangle`) is an existing dependency. 01-RESEARCH.md's Package Legitimacy Audit records zero new packages this phase |
